# JIT calls across distant allocations

Issue #576 records the user-supplied Linux failures of `differential_over_repository_sources` on proof PRs #442, #553 and #556. Cranelift 0.125.4 panics at `compiled_blob.rs:61` converting an x86 PC-relative displacement to `i32`; the reported failures include both negative and positive overflow. That identifies an out-of-range relocation. It does not identify the exact function edge or establish that the fixture's four 512 MiB worker stacks caused the placement.

The pinned module implementation marks `Local` and `Export` functions as colocated. x86 code generation consequently emits a direct `X86CallPCRel4` relocation. The actual Bazel JIT dependency enables `selinux-fix`: its default system memory provider allocates independent anonymous mappings without a distance guarantee. A module's functions can therefore require a displacement outside the signed 32-bit range.

The ordinary, instrumented, batch and session JIT paths now declare their ordinary defined functions `Preemptible`. This is a definable linkage that does not imply colocation. The pinned JIT resolves an already compiled definition to its actual code pointer before consulting external symbols; non-PIC far references lower to an absolute `Abs8` address and an indirect call. Existing object compilation retains its `Local`/`Export` policy, and the AOT wrapper signatures used by the accepted Windows backend are preserved. This change adds no fixed JIT arena capacity.

The Linux x86_64 unit regression owns one anonymous, inaccessible virtual reservation with two tiny code pages separated by exactly 4 GiB. Only those pages receive backing/protection changes. It compiles a real Vesper helper/caller through production lowering, independently inspects the resulting machine relocations, and exercises both address orderings. The old final-linkage policy must produce a near relocation and fail during actual finalization. The JIT policy must produce an `Abs8` relocation, finalize and return 42 by calling the helper across the forced gap. A second test runs the ordinary, instrumented, batch and session entry points. No generated pointer escapes its owning module, and the forced reservation is freed after calls return.

The repository-wide differential fixture is unchanged: it keeps the complete corpus, evaluator/native comparisons, four workers and original stacks. Protocols, proof validators, test timeouts and runtime request/cancellation budgets are outside this patch.

Validation on isolated base `2969db0103c3ee81e5c31ab17b9009e0ea85a42f` uses actual pinned Bazel 9.3.1 and Rust 1.100.0:

- The two final-source unit tests pass. Both address orderings reproduce the original `compiled_blob.rs:61` panic (`NegOverflow` and `PosOverflow`) with actual `X86CallPCRel4` relocations; both corrected `Abs8` calls return 42. The ordinary, instrumented, batch and session entry-point checks pass too.
- The existing native batch, source suspension and native coverage CLI targets pass all 19 tests. They ran before one test-only Clippy correction: mapping an ordinary upstream error to a string inside the negative-control closure. Exact source reconstruction confirms all production bytes are identical; the final unit tests and strict Clippy were rerun after that correction. The initial lint failure is retained rather than counted as a pass.
- The unchanged complete self-hosted front-end target passes both tests in 237.28 seconds of Rust test time (275.106 seconds reported by Bazel). It covers all 301 sources with four workers: 301 token matches, 233 CST matches, four unsupported cases, 64 rejected cases and 23 native cases, with zero failed or ignored tests.

Actual strict Clippy passes on the root unit target and the three native integration targets with `-D warnings`. Scoped Rustfmt 1.100.0, build-file synchronization and whitespace checks pass. Commands, copied test logs/XML, executable identities, source hashes and the test-only lint delta are recorded in `/tmp/jit-far-call-relocations576-validation-v1/actual-validation-receipt.json`, SHA256 `1ccaf57c4ecefd1f9e3c6aa4a333592f2a1a305b031d12df7d25a6c57cb88229`.

This is scoped Linux validation, not a hosted whole-suite or macOS/Windows pass. The four original worker stacks remain unchanged, and their role in the original placement is unproven. The new accepted FFI lowering has separate generated helper/data references outside ordinary-instance declarations; those require a separate integration audit before claiming a distance guarantee for that path.

## V2: generated helper and data references

Accepted main `c64c786d` adds local FFI machine-code helpers and exported mask data. Changing ordinary function declarations alone does not cover their final-linkage references. The JIT policy now also clears `ExtFuncData.colocated` and `GlobalValueData::Symbol.colocated` in every lowered ordinary function after instrumentation and before observation/machine-code generation, including batch definitions, session ordinary definitions and the separately generated session ABI entry. Object policy returns without mutating IR. No FFI-module bytes, helper declarations, collision checks, leaf machine code or MPK behavior are changed. Existing object compile and session APIs remain unchanged.

A second forced-range control retains actual Local helper and Export data declarations. With two tiny pages at opposite ends of an owned four-GiB virtual reservation, unchanged object-policy references reproduce near-relocation overflow in both address orders. JIT-normalized helper calls and data addresses emit actual `Abs8` relocations and execute to return 42. The data page is read-only after finalization; code is executable/read-only. The original ordinary-call controls and all ordinary/instrumented/batch/session smoke checks remain enabled. These tests exercise the relocation mechanism without executing MPK instructions.

Final-source validation: the genuine pinned Bazel filtered unit target passes all three tests, zero failed or ignored, in 54.629 seconds. Strict root-unit Clippy passes in 37.286 seconds with the repository warnings policy. A fresh unchanged complete frontend corpus run passes both tests and all 301 sources in 309.338 seconds (Rust 248.62 seconds), retaining four workers and the exact 233 matched / 4 unsupported / 64 rejected CST tally and 23 native cases. Source-bound commands, logs, XML and binary identities are retained in `/tmp/jit-far-references576-v2-validation/receipt.json`. Earlier v1 native-integration results remain bound to their original source and are not relabeled as v2 runs. No macOS/Windows or live merged-main result is inferred.
