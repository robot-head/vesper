Issue #575 follows PR #412's Linux failure in `lsp::lens_tests::proof_lens_records_proved_failed_and_stale_requests`: the proof response was `failed` with `start process: Text file busy (os error 26)` instead of `proved`. The fixture wrote executable scripts in the multithreaded test process. `fs::write` closes its own descriptor before returning, but a concurrently forked child can retain an inherited writable descriptor until it executes another program or exits. `FD_CLOEXEC` closes a descriptor at exec, not at fork. Linux refuses to execute the script while that other writable descriptor remains open.

A deterministic owned Python fork experiment reproduced this mechanism in three trials. The parent closed its writer, `/proc/<child>/fd` and `fdinfo` identified the matching inode in a waiting child, and the child's descriptor remained close-on-exec. Executing the completed fake-Lean-shaped script returned OS 26. Releasing and reaping the holder made the identical script execute successfully. A separate writer-process experiment also passed three trials: its active writer was an OS-26 negative control; the test parent and an unrelated fork child held no matching descriptors; after the writer exited, the script executed while the unrelated child remained alive. This proves the descriptor mechanism, not the original hosted interleaving. The experiment did not run the actual Bazel lens target.

`fake_lean::Toolchain` now writes each script in a short-lived `/bin/sh` process and waits for its successful exit before making the script executable and returning the configuration. A fixed `printf` command receives the path and complete body as positional data. The test process never owns the writable executable descriptor, so its unrelated forks cannot inherit that writer. Lean and auditor script templates, including compilation delays, theorem records, accepted/rejected outcomes and forbidden-axiom controls, remain unchanged. Production process launching and error handling do not retry OS 26.

Directory ownership is separate. The old label/PID path was deleted before reuse. The fixture now reserves a label/PID/counter candidate with atomic `create_dir`, retries only `AlreadyExists` within 128 candidates, and never deletes an unowned candidate. Its existing `Drop` removes only the directory it created. A two-child experiment using an intentionally identical logical PID prefix reserved distinct directories and preserved a preexisting sentinel. It models a shared temp root with colliding PID-derived names; the hosted namespace and temp-root configuration are unknown.

The new fixture regression keeps two identically named accepting/rejecting toolchains alive, requires distinct directories, executes both version/prefix protocols and both auditor outcomes, and checks that dropping one leaves the other's script bytes intact. On Linux it deliberately holds a writable script descriptor in an isolated helper child, requires a real OS-26 refusal, waits for that child to exit, and executes the unchanged script successfully. Keeping this negative-control writer outside the test process avoids reintroducing inherited writers through parallel test-thread forks. Every existing lens test body and assertion is unchanged.
