## Finite language and actual source binding

Four result kinds: u8, u32, u64, i64. Six arithmetic operations: checked add,
subtract, multiply, and wrapping add, subtract, multiply. Programs have at most
three typed input parameters, at most three sequential typed immutable copy
locals, and one final result. The normal generated corpus uses exactly two
inputs. All valid referenced values have the program result kind. A differently
typed unused input may exist in negative fixtures; the reference checker must
not reject it merely for being unused.

All code is a postfix occurrence tree: no child IDs, DAG sharing, branches,
recursion, arbitrary calls, casts, or unary arithmetic node. Negative literals
are literal values; the real Rust parser folds the minus sign. Across all local
initializers and the result: at most 63 nodes, expression depth at most 8, and
at most 3 locals. Local references resolve only to earlier bindings. Every code
has exactly one resulting stack entry. Intrinsic arity is at most 3 on the wire
so wrong-arity fixtures can be represented; valid arity is exactly 2.

The corpus renderer emits a real typed `f` with explicit input/result/local
types and a Fail[ArithOverflow] row when `allow_fail` is true. A real zero-arg
`main` handles arithmetic failure and returns `(bool, K)`: successful execution
returns `(false, value)`; overflow returns `(true, 0)` of the same kind. The
handler uses the existing actual language syntax, not an evaluator shortcut.
Expressions are fully parenthesized and only the three known wrapping
intrinsics are called. Input/local names are x0..x2/t0..t2; unresolved slots
render with the same index naming rule. The not-callable fixture calls x0.

The exact rendered source is parsed with the actual parser and checked with
the actual checker. Before execution, corpus-owned `validate_rendered` walks
the actual parsed module and normalizes f's declared input/result kinds, input
arguments supplied by main, ordered typed locals, arithmetic/calls/references,
Fail row, and main's handler/tagged-result wrapper back to the supplied DTO.
Require exact equality with the intended Program and fixed wrapper, rejecting
extra functions/statements/operators, wrong argument order or omitted locals.
This binding check is independent of the source printer's string assembly.
Parser-rejected negative literals are the explicit exception: no parsed module
exists; compare the actual parser phase/code to the independent Lean response.
No manually constructed Rust AST replaces that binding.
Unsupported or malformed profile data fails before rendering/execution. The
rendered source cap is 16 KiB, enforced before handing it to compiler APIs.
The checker checks every initializer and result before execution; an earlier
runtime overflow does not hide a later static error. Local initializers are
strict, including unused locals. Inputs supply runtime values only: they never
become static constant facts. Known local facts propagate only through actual
syntactically constant arithmetic under the reference checker's stated policy.

## Static Lean API and reference semantics

Module `ArithmeticOracle` imports `RewriteWitness` and bundled Lean IO/JSON.
Namespace `Vesper.ArithmeticOracle` reuses `Vesper.RewriteWitness.Kind`, `Value`,
`Fits`, `IntOp`, `checkedValue`, `wrappingValue`, `toInt`, `literalValue`.
It must preserve each declared kind; width64 does not identify u64 and i64.
No caller-supplied theorem, environment, executable path, or Lean syntax.

Exact model API (Lean structure fields have the stated names):

```lean

inductive Callee where | intrinsic (op : IntOp) | variable (scope : Scope) (slot : Nat)
inductive Node where
  | intLiteral (n : Int) | boolLiteral (b : Bool)
  | variable (scope : Scope) (slot : Nat)
  | checked (op : IntOp) | call (callee : Callee) (arity : Nat)
abbrev Code := Array Node
structure Input where
  kind : Kind
  value : Int
structure RawProgram where
  kind : Kind
  inputs : Array Input
  locals : Array Code
  result : Code
  allowFail : Bool
structure CheckInfo (k : Kind) where
  constant : Option (Value k)
  potentialOverflow : Bool
```

`ValidatedProgram`, `ValidatedCode`, and `CheckedProgram (k : Kind)` have private
success constructors; successful validation records bounded shape/depth facts.
`CheckError` has `kind : CheckErrorKind` and ordinal `blame : Blame`.
`CheckErrorKind` cases are unknownVariable, typeMismatch, literalOutOfRange,
literalParseRange, missingFail, callArity, notCallable.

```lean

  (code : ValidatedCode) : Except CheckError (CheckInfo k)

```

The concrete validated wrapper exposes a read-only `kind` accessor so the
dependent `CheckedProgram p.kind` signature is legal. Driver framing maintains
sequence/counters outside pure `processRequest`; it supplies the expected frame
ID even when malformed payload has no usable ID. The file exposes a root-level
`main : IO Unit := Vesper.ArithmeticOracle.run` for actual `lean --run`.
`EvalResult` cases: value(Value k,steps), overflow
steps, fuelExhausted steps, invariantFailure. Internal impossible resolution,
stack, or type faults become invariantFailure, never arithmetic overflow.

Each raw node visit consumes one global unit of execution fuel, including all
strict local initializers, then final code. Local reads copy computed values.
The evaluator does not re-execute initializer trees on each local read. Static
checking precedes execution of the complete program. A known checked overflow
initializer is statically admitted with allowFail true; with allowFail false,
any checked operation not independently proved safe from two known constant
facts yields missingFail. Inputs are never facts, even when data happen to be
zero. Wrapping facts use model arithmetic; checked facts exist only on success.

Resolution/checking order for isolated negatives is deterministic: resolve a
variable callee first, unknown => E0201; a known integer callee => E0206
regardless of its kind. Intrinsic wrong arity => E0207. Referenced different-kind
input/bool expression => E0200. Unknown/forward local => E0201. A source literal
whose magnitude exceeds u64MAX, with either sign, exceeds the actual parser
limit => E0002 before kind
range => E0209; other out-of-kind integer literals give E0209. Control numbers
are not literals. Out-of-range explicit input data is invalid_request(input_range).
Do not compare complete general diagnostic sets or source spans to Lean blame.

## Wire protocol and bounded parsing

Every frame is four unsigned little-endian length bytes followed by exactly
that many payload bytes. Read header/payload using exact loops handling short
reads. Reject length above the local cap before allocating payload. The static
Lean server has a fixed65536-byte request cap; the Rust encoder defaults to
16384 bytes and may configure at most65536. A response is at most512 bytes. Every response
is flushed. One request is outstanding at Lean; IDs start0, increase by1, and
are at most9999999999. Terminate fatal(sequence_limit) before counter/ID overflow.

Before Lean.Json.parse: ASCII only, array-only JSON, no objects or backslash
escapes, nesting at most4, at most1024 scalar tokens; strings at most40 bytes;
scalar controls unsigned decimal with at most10 digits, no fraction/exponent/
minus; whitespace only JSON ASCII whitespace. Semantic value strings are
canonical signed decimal (`0`, nonzero positive, or minus nonzero), no leading
zeros or negative zero. Node controls additionally obey their small tag/cap.
Every decoded semantic integer string must fit signed i128, the shared Rust DTO
domain; otherwise invalid_request(decimal), even if its text fits40 bytes.
Boolean data/control are0/1 JSON numbers. Request shape:

```
[1,id,kind,fuel,allow_fail,typed_inputs,local_codes,result_code]
typed_input = [kind,"signed_decimal"]
node = [0,"signed_decimal"]       // int literal
     | [1,index]                  // input reference
     | [2,index]                  // local reference
     | [3,op]                     // checked binary postfix operation
     | [4,target,selector,argc]    // call after argc operand trees
     | [5,bool01]                 // designated bool negative
```

kind0=u8,1=u32,2=u64,3=i64; op0=add,1=sub,2=mul;
target0=intrinsic (selector is op),1=input variable,2=local variable.
Index controls <=65535, but must remain resolvable checker negatives: validation
does not reject an unknown or forward index as malformed. Invalid intrinsic
selector is invalid_request(op_tag). Shape validation uses declared arity to
consume postfix operands, rejects underflow/extra roots; it does not reject
wrong intrinsic arity as malformed. Aggregate63nodes/depth8/inputs3/locals3,
fuel0..4096. Inputs fit their declared kind independently of result kind.

Responses have these exact array shapes:

```
[1,"ready",1,"4.24.0","vesper.arith.checked/1",63,8,3,3,4096]
[1,"value",id,"signed_decimal",steps]
[1,"overflow",id,steps]
[1,"diagnostic",id,"E0209","literal_range",[scope,slot,node]]
[1,"fuel_exhausted",id,steps]
[1,"invariant_failure",id]
[1,"invalid_request",expected_id,"category"]
[1,"fatal","category"]
[1,"bye",seen,checked,diagnostics,invalid,values,overflows,fuel_exhausted]
```

Diagnostic pairs are exact: unknown_variable/E0201, type_mismatch/E0200,
literal_range/E0209, literal_parse_range/E0002, missing_fail/E0401,
call_arity/E0207, not_callable/E0206. Blame scope0=input,1=local,2=result;
result slot0, node is postfix ordinal. It is not a Rust span. Diagnostic
responses have their actual code/class pair, not always the illustrative E0209.
Invalid categories: schema, lexical, json, shape, profile_limit, decimal,
input_range, kind_tag, op_tag, unsupported_profile. A complete invalid payload
consumes the expected ID. Fatal categories: frame_limit, truncated_header,
truncated_payload, io, sequence, sequence_limit; nonzero exit follows.

EOF at a header boundary alone yields BYE and exit0. `checked` equals values+
overflows+fuel_exhausted; `seen` equals checked+diagnostics+invalid. No normal BYE
follows invariantFailure. Normal harness pass requires no fuel/invariant/
invalid/fatal response, exact expected IDs, matching BYE counters, clean EOF and
exit0. Fuel zero is a deliberate negative probe and must not visit a raw node.
Missing/duplicate/extra/out-of-order/truncated/oversize response, crash or stderr
overflow is harness failure, never a skipped corpus case.

## Real execution and process isolation

`run` requires actual Lean exactly4.24.0 and an existing actual harness worker
binary. Missing/wrong tools fail hard in default tests. Copy the exact bundled
RewriteWitness/ArithmeticOracle bytes to regular files in a fresh private temp
root, compile static dependencies with the actual pinned compiler, and run one
long-lived `lean --run ArithmeticOracle.lean`. Use explicit LEAN_PATH for the
private root and known compiler libraries; ambient same-named models cannot
substitute. Never feed compiler-generated Lean or case source through stdin.
Only one Lean oracle process is used per run; a restarted oracle makes that run
incomplete/failing, not a continued single-process pass.

Rust worker subprocesses use the same real harness binary's private `--worker`
mode. They receive bounded framed case data and return all Rust outcomes, not
Lean answers. The parent retains the oracle result and compares independently.
Worker IPC cap64KiB per frame; response diagnostic codes <=16, each<=16 bytes;
error details<=4096bytes. It uses the same exact-read framing discipline. Worker
requests carry `worker_seq`, `case`, evaluator fuel; replies echo sequence+case
ID plus RustAnswer or bounded HarnessError. Private control shapes are validated
before compiler entry. This transport cannot make a malformed answer a pass.

For each valid case actually execute all eight comparisons against Lean:
original/optimized AST × IR disabled/enabled × evaluator/native JIT. Parse once,
check original, optimize an actual cloned module with actual TypeMap, recheck
optimized module; use the two resulting checked Worlds. For each World execute
two Runtime settings and two jit_with_options settings. Runtime::optimize is
set explicitly and fuel set100000. Each JIT is a real compile/finalize/execute,
not an evaluator result relabeled native. Decode against the checked return
type: Tuple length2 and Bool tag. Native results require UInt matching8/32/64
for unsigned or Int for i64. The evaluator may retain an unsuffixed Int inside
an unsigned aggregate; accept it only when its unchanged mathematical value
fits the declared kind. Never mask, truncate, reinterpret negative Int as
unsigned, or accept a mismatched explicit UInt width. Overflow must carry
numeric zero under that same typed interpretation, otherwise decoding fails.
Backend errors, unexpected tuple layout, timeout, panic or fuel exhaustion are
harness failures; never map arbitrary errors to overflow.

The public JIT API creates a fresh module per invocation and exposes no reusable
compiled handle. Its underlying executable allocations are intentionally not
freed on module Drop. Recycle each Rust worker after32 handled corpus frames by
default, HARD128, including static-negative cases. For jobs1 with the default
batch cap, the128-valid/15-negative suite uses five workers and four recycles.
Do not change native APIs or use unsafe free tricks. Wait/reap old worker before
replacement, keeping live workers <=jobs (1..4). No hard process-RSS claim.

Parent OS watchdogs enforce startup/response/case/shutdown deadlines. They kill
and reap timed-out processes; no claim of interrupting an in-process JIT call.
Bound stdout frame buffers and drain stderr concurrently up to64KiB; overflow
sets a fault and parent kills/reaps. Kill/reap before joining blocked pipe
threads. Use bounded channels without cleanup deadlock (try_send/fault state or
drain before join). Do not trust child-reported elapsed time for enforcement.

One case is outstanding per Rust worker. A bounded ordered window of at most
4*jobs (HARD16) cases includes queued and completed-but-uncommitted results.
Lean is serial, workers may run concurrently; do not buffer the whole corpus.
Commit comparisons/hashes in increasing case ID. On error stop dispatch, settle
lower outstanding IDs within their deadlines, select the deterministic lowest
failed ID, then cancel/reap higher work. Count only operations actually executed;
cancelled/undelivered cases cannot become passes. Already-running higher cases
may complete, recorded separately from committed valid comparisons. Operation
counters count completed calls confirmed by a worker response. An interrupted
worker may have unreported partial activity: record interrupted_worker_cases
and do not invent exact call counts for its lost response. All counters are
exact for successful completion; failed reports explicitly describe confirmed
lower bounds where interrupted_worker_cases is nonzero.

## Portable transport-only fault probes

The independent acceptance lane owns `fault_peer.rs`, compiled in debug and
release builds of this developer-only oracle binary so actual release-profile
integration tests use the same genuine executable. The coordinator's thin
binary privately dispatches exclusive `--fault-peer MODE` to it. It never
enters normal run(), supplies numeric oracle answers, or emits a RunReport.
Allowed modes: malformed, oversize, truncated_header, truncated_payload, stall,
stderr_flood, reordered, bad_bye, short_writes, crash. Short_writes exchanges only a fixed transport marker; it is
not a language value or an oracle success response. No arbitrary script/Lean
replacement is used as positive evidence.

Runner-owned `#[cfg(test)] process::testing` provides a bounded probe API using
the SAME production framing, concurrent readers/writer, ready/answer/BYE
parsers, OS deadlines, and kill/reap/thread-join cleanup. It does not implement
a second transport that could pass while the real runner fails. Its exact
DTO/signatures are:

```rust
// All types Debug + Clone; enum also Copy + Eq + PartialEq.
pub enum ProbeKind {
    Malformed, Oversize, TruncatedHeader, TruncatedPayload, Stall,
    StderrFlood, Reordered, BadBye, ShortWrites, Crash,
}
pub struct ProbeLimits {
    pub frame_bytes: usize, pub stderr_bytes: usize,
    pub timeout_ms: u64, pub shutdown_timeout_ms: u64,
}
pub struct TransportProbeReport {
    pub kind: ProbeKind, pub observed: Option<FailureKind>,
    pub child_reaped: bool, pub reader_joined: bool, pub writer_joined: bool,
    pub stderr_joined: bool, pub max_frame_bytes: usize, pub stderr_bytes: usize,
}
pub fn probe(command: std::process::Command, kind: ProbeKind, limits: ProbeLimits)
    -> Result<TransportProbeReport, HarnessError>;

// Independent fault_peer.rs, registered by coordinator's thin binary:
pub fn run(mode: &str) -> Result<(), crate::oracle::HarnessError>;
```

Probe limits are positive and respectively <=65536 bytes,65536 bytes,120000ms,
5000ms. Report max_frame_bytes and stderr_bytes are retained bytes, <=local
caps; an overflow fault is detected even when excess bytes are not retained.
`observed=None` only for the fixed-marker ShortWrites roundtrip; otherwise the
failure classification comes from actual production parsing/process control,
not a lookup of the requested kind. Tests assert expected failure separately.
Actual wait/reap and pipe thread joins determine the booleans; they are not
inferred from sending a kill request.

Exact peer behavior: malformed sends a frame containing b"["; oversize sends
header65537 without payload; truncated_header sends only2 header bytes;
truncated_payload sends length5 then b"[" and EOF; stall parks without output;
stderr_flood writes65537 bytes then parks; reordered emits a framed
invalid_request response with id1 while the probe expects0 (no numeric value);
bad_bye emits BYE with seen1 and all other counters0 when production expected
all0; crash exits23. Short_writes sends only b"oracle42-transport-marker" as a
frame, flushing each header/payload byte individually; the production frame
reader compares that fixed marker without invoking semantic answer parsing.
Production ready parsing is also directly covered by runner tests and the real
Lean handshake; malformed/protocol sequences must not be converted to a marker.
Unit short-read/write adapters additionally force short operations because OS
pipes may coalesce individual writes. A fault peer cannot choose arbitrary
payloads or supply a valid language value. The probe chooses the corresponding
production parse operation (answer/terminal/frame) and expected sequence/counter.

The probe takes an explicit Command, bounded caps and a closed plan,
returns only TransportProbeReport, and cannot bypass run()'s actual tool
version/source checks or produce a RunReport. Integration tests launch the
genuine CARGO_BIN_EXE binary with its private peer mode. Verify actual process
reaping and bounded buffers, not a mocked boolean or only error text. No
cross-platform claim relies on a shell fake executable.
