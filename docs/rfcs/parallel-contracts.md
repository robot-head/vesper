# Parallel integration contracts: proposed v1 boundaries

Status: audit and proposals, not implemented interfaces or new soundness theorems. Evidence is the expanded `docs/specification.txt` at checkpoint `c5328d0`. Line references below address that snapshot. Source references use checkpoint paths; the completed workspace extraction moves AST/numeric to `vesper-core`, syntax to `vesper-syntax`, and frames/driver/scheduler to `vesper-pulse` without changing their semantics.

The checkpoint has a working compiler, finite native specialization, executable Lean extraction, relative-address data frames, and a reference-evaluator I/O bridge. It does not have a machine-stack suspension ABI, allocation/region typing, public `.vhir` format, package confinement, traits/macros, or the expanded platform libraries. Independent libraries can proceed now; shared semantic changes require the owner decisions below.

## Decisions needed before connecting lanes

| Contract | Evidence and integration risk | Minimal v1 decision and owner |
| --- | --- | --- |
| Arithmetic semantics | §11.2, line 1194, specifies checked `+`, `-`, `*` with `Fail[ArithOverflow]`; the checkpoint deliberately uses wrapping arithmetic (`src/numeric.rs`, `src/optimize.rs`, native/evaluator/Lean backends). The original core did not settle overflow. | Treat checked overflow as a new normative migration task, not a request for user permission. Core owner defines error type, checked/wrapping operations, and literal/optimization rules; native and Lean owners implement the same versioned semantics. Until then, retain and label existing wrapping behavior. Preserve the separately user-approved field premise `k_i ⊑ m_i`. |
| Scoped child borrows | Core [T-Abs] rejects closure capture of `in`/`inout` bindings; §12.4, lines 1607–1647, spawns closures borrowing parent projections. Current checker enforces the ban (`src/check.rs`, closure checking). A normal owned closure cannot silently become a scoped borrower. | Core + Pulse owners choose a dedicated scoped-child closure/loan judgment. Specify join scope, child loan ownership, cancellation restoration, and whether the closure can be stored or escape. Initial v1 may support owned captures only and reject borrowed captures explicitly; do not relax ordinary closure capture rules globally. |
| Native suspension and relocation | §12.5/12.7, lines 1656–1739, store physical SP, state/header pointers and native saved registers; `sqe.user_data` is described as a header pointer. §12.3 permits kernel DMA into suspended stack fields. These addresses are not made relocatable solely by banning source reference types. Current `FrameStack` relocates data addressed by IDs; native `src/native.rs` still uses physical stack slots/pointers. | Native + Pulse owners define machine ABI version 1 and an explicit relocation eligibility state. Never move storage while the kernel can access it. Use stable request IDs, as the existing driver does, rather than movable header pointers. Choose relative/rebased representations with complete metadata, or keep machine activations address-stable in v1 and report machine relocation as unsupported. Specify actual target calling conventions and saved-register layouts; document timing/size numbers as unvalidated targets. |
| Cancellation completion | §12.3, lines 1595–1603, says `cancel_and_reap` waits for a CQE, without making cancellation-command CQEs and original I/O CQEs distinct. Releasing a buffer on the former can race DMA. | Pulse owner preserves the existing driver invariant: only the original I/O completion releases its request, file, buffer and continuation. Cancel acknowledgements are separate bookkeeping. Publication/submission failure returns ownership; poll errors return every harvested completion; shutdown preserves still-pending owners. |
| Region aliasing and rewind | §15.2, lines 1975–1988, makes `RegionBox[r,T]` copy for copy `T`; distinct copied handles may denote the same cell, so root-name disjointness is insufficient. Scope non-escape alone also does not prevent a live copy handle from becoming stale after `rewind(mark)`. Current type syntax has no region-binder kind and native layouts have no owning heap representation. | Core + Strata owners specify read-only shared handles versus region-exclusive mutation, alias-origin identity, and epoch/watermark invalidation. Conservative v1: immutable copied handles, explicit exclusive region access for mutation, and no rewind while affected views can be used. Define affine finalizers and linear payload consumption before reuse/reset. Do not infer these properties from the two displayed region rules alone. |
| Portability and thread affinity | §12.1/12.4 distinguishes portable work-stealing and local tasks; §18.4 requires UI-thread confinement. The current ownership `Mode` has only copy/affine/linear and carries no portability proof. A runtime `is_portable` boolean alone cannot justify moving captured values or capability state to another worker. | Core + Pulse owners model portability/thread affinity separately from the ownership lattice. Until compiler-derived evidence covers captures, borrowed parents and handler state, schedule locally. Do not add `portable` as another rank in the existing ownership total order. |
| Authority versus discharged rows | §8.2, lines 504–510, requires package confinement, while §15.2, line 1988, permits pure bounded scratch regions. A handled outgoing effect row is not an authority audit: local handlers can discharge effects, and macros can inject privileged callees. | HIR + Loom owners separate package-qualified authority requirements from a function's residual lexical effect row. Define privileged OS/FFI/allocator handler construction and a bounded stack-scratch exception, if desired. Export audited direct/transitive requirements with package-qualified effect IDs and kinded arguments (e.g. `Ffi[LibA]` must not collapse into the same string as `Ffi[LibB]`); never certify a package ceiling merely by inspecting its public outgoing rows. |
| Interface/ABI/build cache keys | §8.2/8.3 promises body-only early cutoff; §9 allows private representation evolution; §10 line 1158 maps interface MIF directly to `.o` archives. A body-only fix can preserve MIF but must produce new code. Private layout changes can also change the current inline native calling ABI. Current `World`/AST are experimental representations with source spans and ephemeral capability labels. | Integration + SemVer + Loom owners distinguish canonical source-interface identity, implementation/derivation identity, and target ABI/layout identity. Object lookup must include implementation inputs. Recompile callers whose concrete ABI or specialization inputs changed, or use an explicitly stable opaque ABI. Do not serialize `World` or `$cap{span}` labels as the public interface format. |
| Lean artifacts and totality | §11.2 promises total bare pure functions and says termination measures are optional; arbitrary accepted recursion is not thereby total. Current extractor uses executable `partial def`. §11.4, lines 1320–1330, treats preserved theorem statements as proof stability even when definitions/model dependencies can change. | Verification owner distinguishes executable partial extraction, termination-checked models, and proved theorems. Bind certificates to Lean version/options, model and transitive imported-definition hashes, not only statement MIF. Audit actual transitive axioms in the Lean environment. A generated `.lean` file or matching statement set is not a compiler-correctness certificate. |
| Wire validity and alignment | §13.2, lines 1754–1758, requires total bit validity/no implicit padding and also a packed 61-byte Kafka header. Natural C alignment would insert gaps, e.g. CRC follows a one-byte magic field. `ZeroPad` is zero-initialized, which needs a policy for arbitrary foreign bytes. | Bridge + layout owners agree byte-aligned endian wrappers versus naturally aligned native scalars, total-bit-valid fields versus separately checked canonical zero padding, and exact nested/tail layout. Zero-copy byte access must not create misaligned Rust/native typed references. Require serialized layout metadata shared with SIMD and shader reflection. |
| Macro capability provenance | §16.4 [T-MacroConfinement], lines 2260–2263, limits macro-originated code. The sample verifier at lines 2406–2432 only examines pre-resolved IDs whose defining package is the macro's own package. An injected dependency call, handler, or late-resolved reference can fall outside that test. | Forge + HIR + Loom owners define origin-of-emission metadata independent of definition ownership, then check all introduced/resolved operations and transitive authority. Unquoted caller syntax keeps caller origin; generated tokens cannot assert their own trusted provenance. Unknown resolution fails closed. |

## Small versioned boundaries to agree first

These are proposed contract envelopes. Their owning lanes should publish Rust types and canonical fixtures before consumers depend on them.

| Proposed boundary | Required contents | Owner and first acceptance check |
| --- | --- | --- |
| `PublicInterfaceV1` | Schema and language-semantics versions; package-qualified definition IDs; alpha-normalized generic/row binders; full types, modes, passing/projection contracts and resumption guarantees; visibility/open/sealed policy. Source spans, local IDs and bodies excluded from source MIF. | SemVer + core: body/private-helper renaming leaves source MIF unchanged; changing any exported ownership/effect contract changes it; unsupported comparisons cannot be certified compatible. |
| `AbiLayoutV1` / derivation key | Target triple, ABI version, size/alignment/field offsets/tag encoding, calling convention, concrete specialization dependencies; compiler/options/features/source and implementation inputs separate from interface MIF. | Native + Bridge + Loom CAS: a same-interface body fix selects a new object; a changed private inline layout invalidates ABI-dependent callers; wrong-target objects are rejected. |
| `EffectEvidenceAbiV1` | Capability identity and slot indexing, operation argument/result layout, caller/handler state ownership, one-shot resume/abort transitions, failure and cancellation ownership, portability/thread affinity. Raw register assignment is target-specific implementation metadata. | Native + Pulse: compiled code parks and resumes once with a live linear obligation; cancellation cannot release a DMA buffer early; no interpreter substitution. |
| `RegionAccessV1` | Region identity/generation, immutable versus exclusive access, allocator block ownership, rewind eligibility, affine finalizer order and linear exhaustion. | Core + Strata: copied aliases cannot supply overlapping mutable views; post-watermark handles cannot be used after rewind; an unconsumed linear payload prevents reset/exit. |
| `BuildSandboxV1` | Component/world ABI, fuel/memory limits, input assets, deterministic environment/clock/randomness, output directory policy and emitted-code authority provenance. | Sandbox + Forge: network/ambient file access denied, inputs read-only, `/out` intentionally writable, replay key includes all observable inputs. The prose at line 510 calls both assets and `$OUT_DIR` read-only, while scaffold line 1138 make output writable; adopt the latter explicitly. |
| `ProofArtifactV1` | Model/spec/import/toolchain digests, theorem identity and statements, dependency-qualified axiom audit results and extraction semantics version. | Lean + Loom: altered upstream definitions invalidate dependent certificates even if theorem statements remain textually equal; unapproved axioms block publication. |
| `SimulationJournalV1` | Version, seed, task/request identities, ordered events, virtual time, completion/cancellation distinctions and recorded choices. Opaque continuations move through states rather than requiring `Clone`. | SimPulse + Pulse: replay either reproduces the same trace or reports a mismatch without losing a pending owner; random-seeded scheduling alone is not DPOR. |

## Integration order and scope guardrails

1. Preserve the passing compiler facade during leaf extraction. Shared checked `World`/type metadata must be separated from orchestration before splitting checker and Place IR; current dependencies run in both directions. New lanes should consume declared DTOs rather than importing private checker internals.
2. Merge independent model/layout/calculus/simulation libraries with their own tests and explicit limits. Only the integration owner changes root workspace members, shared dependency pins, lockfile, and shared schemas.
3. Resolve arithmetic, scoped child borrows, native suspension ownership, and region access before integrating source-facing runtime/allocator features. Review ABI/layout and authority metadata together; avoid changing one consumer's copy of a shared type independently.
4. Gate Prism/Aura/Ignis on compilable core examples and the relevant runtime/FFI/platform contracts. Native Windows/macOS toolkit behavior, IOCP/kqueue, MPK/POE, scalable SIMD and GPU barriers need target-specific validation beyond Linux models or AArch64 object emission. The research/performance figures in the design are hypotheses until reproduced.

Two concrete scaffold maintenance items should not become hidden implementation choices:

- §10's workspace member list (lines 708–738) omits `vesper-ignis`, which §19.7 explicitly adds at line 3088. An interim `vesper-core` shared-types crate and a separate simulator crate are integration choices; record them rather than implying the listed architecture already exists.
- §10 pins Salsa 0.22, egglog 0.5, Cranelift 0.116 and Petgraph 0.7; checkpoint versions are 0.24, 3, 0.125 and 0.8 respectively. Preserve working versions unless a separately tested migration is required. Scaffold APIs are illustrative, not a compatible drop-in patch. In particular, §10's PCG sample marks an entire local consumed for a `sink` projection (lines 1006–1009); replacing current subtree tracking with that sample would lose remaining-field obligations.
