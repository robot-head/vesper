## What was built

### SEV-SNP (`src/snp.rs`, `src/amd.rs`)

- Report versions 2–5. Version 4 has the version-3 layout (as in AMD
  firmware and VirTEE `sev`); version 5 adds `LAUNCH_MIT_VECTOR` and
  `CURRENT_MIT_VECTOR` (`SnpReport::launch_mit_vector`,
  `current_mit_vector`; zero, and required zero on the wire, before v5).
  Version 6 (Venice extended TCBs) and below 2 are
  `ParseError::UnsupportedValue`. A v5 report relabelled v3 fails on
  non-zero reserved bytes.
- `SnpReport::product()`: Milan/Genoa/Turin from the v3+ CPUID fields
  (AMD KDS "Determining the Product Name"). `verify_snp_collateral` now
  requires it to equal the collateral's product (typed
  `CollateralMismatch`; an unknown processor is `Collateral`).
- hwID: the raw extension value (AMD KDS) or a DER `OCTET STRING`
  around it (Trustee's "new format" certificate), told apart by length.
- `SnpCollateral::from_kds_cert_chain`: a KDS `cert_chain` response
  (ASK/ASVK + ARK, PEM); the served ARK must be byte-identical to the
  pinned one (the same rule as Intel's embedded root).
- Anti-rollback: `VerifiedSnpReport::crl_this_update` and
  `check_snp_crl_floor` reject an ARK CRL older than one already accepted
  (`AttestError::CollateralDowngrade`), and a missing CRL once one was
  accepted.

### TDX (`src/tdx.rs`, `src/intel.rs`)

- Quote v5: body descriptor (`type u16`, `size u32`) with body types 2
  (TD 1.0, 584 bytes), 3 (TD 1.5, 648: `TEE_TCB_SVN_2`, `MRSERVICETD`) and
  4 (TD 1.5 ex, 885: VM index, TD ID, device-info hash, initial/current
  service-TD hash and attributes, initial CPUSVN/TEE_TCB_SVN/FMSPC). The
  size must be exactly the type's size; type 1 (SGX) and unknown types are
  errors; VM index above 3 is an error. `TdxQuote::td15`, `td15_ex`,
  `body_type()`; the attestation key signs header, descriptor and body.
- `evaluate_tdx_current_tcb`: for TD 1.5 bodies, the TCB evaluation is
  also run on `TEE_TCB_SVN_2` and must find a level, as Intel's QVL
  requires; the result is `VerifiedTdxQuote::current_evaluation`.
- Platform-instance PCK certificates: `PckExtensions::issuer`
  (`Processor`/`Platform` CA, from the issuer CN) and
  `platform_instance` (`PlatformInstanceID`, optional `Configuration`
  with each of its three booleans optional). A Platform CA certificate
  without an instance ID, a Processor CA certificate with instance
  entries, duplicated or unknown configuration entries, and other
  issuers are typed errors.
- Anti-rollback: `TdxCollateralFloor` (minimum
  `tcbEvaluationDataNumber`, TCB info and QE identity `issueDate`),
  `raised_by` (componentwise maximum; never lowers) and
  `check_tdx_collateral_floor`. Real test: the `dcap-qvl` 0.3.4 quote and
  collateral (FMSPC `B0C06F000000`, number 17) verify on their own and are
  refused as a downgrade after the 0.7.1 collateral for the same FMSPC
  (number 20) was accepted.
- QE identity and TDX module levels may carry only `UpToDate`,
  `OutOfDate` or `Revoked` (Intel's enclave-identity statuses); anything
  else is a typed error. Convergence ignores other statuses, so accepting
  them would have silently dropped them.

### Arm CCA (`src/cca.rs`)

- Both collection encodings: tag 399 (byte-string values) and the CMW
  collection tag 907 whose members are `[263, bstr]` records
  (`CcaToken::collection`).
- Profiles: platform `http://arm.com/CCA-SSD/1.0.0`,
  `tag:arm.com,2023:cca_platform#1.0.0`, `tag:arm.com,2024:cca_platform#2.0.0`;
  realm absent, `…2023:realm#1.0.0`, `…2024:realm#2.0.0`. Unknown profiles
  are errors.
- Measurements: RIM/REMs at the hash length or at RMM's 64-byte buffer
  size.
- Platform keys: `verify_cca_certified` (X.509 chain to a configured root,
  as before) and the new `verify_cca_endorsed` (Veraison-style
  endorsements: exactly one endorsement for the instance ID, optional
  implementation ID match, CPAK signature). Both then check the realm
  signature and the RAK binding; `cca_vesper_claims` adds the Vesper
  binding. `verify_cca_token` keeps its signature and behaviour.

### Lean (`lean/AegisCollateral.lean`)

A model of `evaluate_tdx_tcb`: Intel's seven statuses with a partial order
(revoked, or needs at least the same updates; `OutOfDate` subsumes
software hardening; `ConfigurationNeeded` and `OutOfDate` are
incomparable), ISV statuses `UpToDate < OutOfDate < Revoked`,
first-match selection over level lists, component-wise SVN comparison,
evaluation in the Rust order (module identity, platform, QE identity) and
`converge`. Proved, about the model only (12 theorems, no `sorry`, axioms
at most `propext` and `Quot.sound`):

- `converge_monotone`, `sle_trans`, `vle_trans`;
- `find_monotone`: over a list sorted best to worst, raising the evidence
  never selects a worse level and never loses the level;
- `evaluate_monotone`: raising every SVN (PCK SGX components, PCESVN, TDX
  components, QE ISVSVN, module SVN) yields a result at least as good, and
  still a result;
- `evaluate_revoked_qe`, `evaluate_revoked_module`;
  `evaluate_module_first`, `evaluate_platform_before_qe` (the order of
  errors);
- `raise_accepts_its_input`, `rollback_rejected`, `accepts_antitone` for
  the anti-rollback floor.

`tests/lean_model.rs` audits the file and, with `VESPER_LEAN` set, compiles
it and compares its printed `converge` table with `TcbStatus::converge` on
all 21 inputs. This is a differential test, not a refinement proof.
`lean/AegisToctou.lean` is unchanged.

## Decisions

1. **Component-wise, not lexicographic.** The `tdx_quote_outdated` sample
   shows the difference on real data; this crate follows Intel's
   published rule and returns `TcbLevelNotFound`.
2. **Launch and current TCB.** Both are evaluated for TD 1.5 bodies and
   returned; `evaluation` (launch) stays the primary status for API
   compatibility.
3. **Rollback is the caller's state.** The library cannot remember what a
   verifier accepted; `TdxCollateralFloor::raised_by` and
   `check_snp_crl_floor` make the check explicit and the floor monotone.
4. **CCA trust without a vendor root.** No silicon vendor publishes a CCA
   chain; endorsed keys by instance ID (Veraison's model) are the real
   deployment form, and TF-A's key is the reference implementation's.
5. **SNP v4 as v3, v6 rejected.** VirTEE `sev` treats v4 as the v3 layout;
   v6 adds Venice extended TCBs that no sample shows.

## Remaining gaps

- **AMD KDS CRLs**: no real CRL was obtainable (`kdsintf.amd.com` is
  blocked from the sandbox and no package or repository searched bundles
  one). Revocation and the CRL floor are generated-chain tests only.
- **Genoa/Turin VLEKs**: the real VLEK sample is Milan; the Genoa and Turin
  ASVKs are pinned and signature-checked against their ARKs only.
- **Arm CCA**: no silicon-vendor chain exists publicly; the TF-RMM token is
  verified against TF-A's reference key, the 2024 token is synthetic.
  Software-component endorsements and reference values (CoRIM) are not
  appraised.
- **SGX quotes** (v3, body type 1) and SEV-SNP v6 are rejected, not
  supported.
- No TEE hardware was used: `attest_channel_binding` still returns
  `TeeError::HardwareUnavailable`.
- The Lean model is about the model; nothing is proved about the Rust code.
