## Session API and lifecycle

The integration-facing, crate-private API is:

```text
ServerError { code:i32, message:String, data:Option<Value> }
NotificationOutcome::Continue(Vec<vesper_lsp::Envelope>)
NotificationOutcome::Exit { clean:bool }
Session::new() -> Result<Session,String>
Session::request(&mut self, method:&str, params:Option<Value>)
    -> Result<Value,ServerError>
Session::notification(&mut self, method:&str, params:Option<Value>)
    -> Result<NotificationOutcome,ServerError>
```

The session performs no transport I/O. Root dispatch decides how to frame results,
errors and notification logs. Before initialization, requests/notifications fail
with `-32002`, except `exit` which reports an unclean exit. Initialization accepts
an object exactly once; duplicate initialization and requests after shutdown use
`-32600`. Shutdown returns JSON null and accepts absent, null (direct API), or
empty-object parameters; the root protocol profile separately rejects null
envelope parameters. Other shutdown parameters fail without changing state.
Exit is clean only following shutdown. Unknown running-state requests use
`-32601` even when parameters are absent. Unknown running-state notifications
are ignored. There is no background cancellation/execution behavior.

Advertised capabilities are UTF-16 incremental sync (`change:2`), hover,
definition, document/workspace symbols, canonical formatting and supported code
actions. Completion, code lenses/proof execution and executeCommand are absent.
Document symbols use DocumentSymbol objects only when the client advertises
`hierarchicalDocumentSymbolSupport:true`; other clients receive current-source
SymbolInformation locations instead.

Code actions are advertised only when both client capabilities are present:
`workspace.workspaceEdit.documentChanges == true` and an object-valued
`textDocument.codeAction.codeActionLiteralSupport`. Otherwise the capability is
false and direct action requests fail `-32003` with
`{status:"analysis_unavailable",kind:"client_capability"}`. Versioned edits are
never downgraded to unversioned WorkspaceEdit changes. Standard formatting still
returns the protocol's TextEdit array and follows the canonical zero-config
formatter; client indentation options do not change its style.

## Transactions, identities and cache bounds

The actual DocumentStore is authoritative. Its defaults enforce 128 KiB per
document, 32 documents, 2 MiB total source, 4,096-byte opaque URI labels, 64
changes per transaction and a bounded mutation work ledger. Changes use the
store's sequential UTF-16 range/rangeLength checks and strict increasing i32
versions. Failed edits, duplicate opens, document/count/size limits and invalid
versions preserve both stored text/version and Salsa mirrors.

Only after successful open/change does the session clone the bounded accepted
text into SourceFile. After 64 accepted open/change transactions, the entire
Database and every SourceFile mirror are rebuilt from current bounded store
contents. Every accepted close also triggers a full rebuild, including all still
open files, and clears diagnostics for the closed URI. No old SourceFile ID is
retained across reset, while store versions and line indexes remain current.
Reopening a URI starts from the newly supplied buffer. These are logical bounds
on synchronous cache history, not hard RSS or latency guarantees.

An iterative direct-DOM guard precedes parameter access/copies: method labels are
nonempty/control-free and at most 256 bytes; parameter nesting is at most 64,
nodes at most 65,536 and aggregate string/key bytes at most 2 MiB. Pending child
counts are bounded before stack extension. The caller owns any pre-existing
Value allocations; the transport additionally bounds serialized bytes/depth and
rejects duplicate decoded keys before constructing its DOM. Position/range/
version integers are checked u32/i32 conversions, never narrowing casts.

## Actual checked providers and explicit unavailable states

Semantic requests and published diagnostics use only `guarded_analysis`, never
legacy parse/check queries. The session retains validated CheckedSource Arcs
only for the duration of a request and pairs them with the current store index.
Hover, definition and symbol results come from the committed navigation provider.
Workspace symbols/search use only current open buffers. URI strings never cause
ambient filesystem reads, workspace loading, JIT, native/WASM builds or proof
execution.

Parse/semantic diagnostics retain actual compiler messages/codes and map actual
byte spans through LineIndex into UTF-16 ranges. Resource/unsupported analysis
is a severity-2 `VESPER_ANALYSIS_UNAVAILABLE` file-level warning at the validated
empty origin range, with explicit unavailable metadata. A diagnostic span that
cannot map to current UTF-16 source discards staged semantic diagnostics and
produces an unavailable warning (`kind:"invalid_compiler_span"`), rather than a
guessed range, false semantic error, stale diagnostic set or server crash.

Publish parameters include `uri`, current `version`, standard `diagnostics`, and
`vesper:{status,kind,source_blake3}`. Status is `checked`, `parse_error`,
`semantic_error`, or `analysis_unavailable`. The hash identifies exact current
source bytes. Checked-source feature failures use `-32003` with source-specific
URI/version/hash/kind/reason/diagnostics data; invalid client params/store
transactions use `-32602`.

`vesper/signatureSearch` takes `{query:object,uri?:open-uri}`. The root structural
query is validated even with no buffers, then current checked Arcs are collected
for the selected URI or all open buffers. A refused buffer causes an explicit
source-specific failure, never an incomplete success. Root
`SearchError::Query` maps to `-32602`; `Unavailable {uri,reason}` maps to `-32003`
with `{status:"analysis_unavailable",kind:"search",uri,reason}`. The root search
profile additionally bounds query serialization to 32 KiB and results to 1 MiB.

Code actions use default Policy only, with no Loom.toml/filesystem discovery.
They recompute actual findings through the existing source action provider;
forged client diagnostics, edits and verification flags are ignored. An absent `only`
filter requests selected quick fixes; an explicit `only` selects matching offered
kinds by LSP hierarchy, including `source`/`source.fixAll` selecting
`source.fixAll.vesper`. Empty/nonmatching filter lists return no action after checking
the selection. Both quick-fix and explicit fix-all preserve full candidate
rechecking and actual supported-interface compatibility. Returned actions carry
versioned documentChanges and source/policy/candidate provenance, and never apply
themselves or change stored source.

## Validation

Private `/tmp/tooling41-lint-target`; one Cargo job, dev/test debug off,
incremental compilation off. Passed with temporary real root dispatch/search
wiring:

```text
cargo check -p vesper --lib
cargo test -p vesper --lib lsp::session::tests
  9 direct session tests
cargo clippy -p vesper --lib --tests -- -D warnings
rustfmt --edition 2024 --check src/lsp/session.rs
git diff --check
```

Tests cover lifecycle/capabilities/error codes; failed UTF-16 and multi-edit
transactions preserving mirrors/versions; all-file reset after 64 revisions and
close with another document open; close/reopen freshness; unsupported warning,
actual semantic diagnostics and recovery; invalid UTF-8/CRLF/out-of-bounds
diagnostic span fallback; legacy/hierarchical symbol negotiation; closed-buffer
refusal; source-specific search failures, malformed queries and a checked
257-item source exceeding documentation extraction limits; absent/false/partial
action capabilities; selected quick-fix versus hierarchical explicit fix-all,
forged diagnostic rejection and versioned edits; deep DOM, source-size and
document-count refusal before mirror mutation. The root integration/Beacon lane
owns real framed stdio acceptance and native-platform full validation.

This session does not implement completion/liveness, PoisonedRecovery, background
proofs, filesystem projects, cross-file dispatch resolution, client auto-apply,
configurable formatting, asynchronous cancellation or sub-2ms performance.
