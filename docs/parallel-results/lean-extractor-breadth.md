`tests/lean_extract.rs`, `tests/fixtures/lean_extract/**`, this report, and a

## The problem this lane solves

Before this change every extracted function was a `partial def` inside one
`mutual` block. Lean compiles `partial def` to an opaque constant, so the
kernel could run the extraction (`#eval`) but could not prove anything about
it: not about structs, enums, `match`, `Fail` or handlers, and not about
recursion. That is the gap Lens records as "the kernel sees only opaque
constants for `partial def`s" and the reason Lens built its own scalar model.

## What was built

### 1. Total definitions in dependency order

`extract_report` collects every Lean definition (CFG-block definitions from
`lean_ir.rs` and generator definitions alike), builds the reference graph
with the new `Term::references()` and orders strongly connected components
callees first:

- A component without recursion becomes ordinary `def`s. CFG block helpers
  (`$block_f_n`) are emitted as `@[simp] def`, so `simp [f]` sees through them
  without naming them.
- A recursive component (a self-reference or a cycle, including mutual
  recursion and recursion spread over CFG blocks) stays one `mutual` block of
  executable `partial def`s, exactly as before, so `#eval` agreement with the
  evaluator is unchanged.

### 2. Recursion and bounded loops: total fuel companions

Vesper has no loop syntax; loops are (tail-)recursive functions over their
loop-carried values, and the source has no `decreases` annotation to turn
into `termination_by`. So every function that is recursive, or calls
recursion, gets a total companion `f$fuel`:

```lean
def «sum_to$fuel» {m} [Monad m] [VesperDiverge m] ($fuel : Nat) [Effect_Fail ArithOverflow m] (i n acc : UInt64) : m UInt64 :=
  match $fuel with
  | 0 => VesperDiverge.diverge
  | Nat.succ $fuel => do … («sum_to$fuel» ($fuel := $fuel) …) …
```

It is structurally recursive on `$fuel`, so Lean accepts it as a plain `def`
(mutual groups become a `mutual` block of `def`s). Running out of fuel is the
prelude effect `class VesperDiverge (m) where diverge : ∀ {A}, m A`, never a
fabricated value; instances are provided for `Option` (`none`), `ExceptT E m`
and `HandlerCPS S O m`, so companions work inside handlers. Pure recursive
functions become monadic in their companion; calls to companions inside a
companion are binds. Theorems are then partial-correctness statements ("if it
returns, …") proved by induction on fuel, or concrete runs proved by `rfl`.

Companions are generated by the existing effectful generator in a new fuel
mode. If one cannot be generated (today: a recursive function passed as a
value), the function is reported `Totality::Partial(reason)` and every
companion that calls it is dropped transitively, so the module still compiles.

### 3. Structs, enums and `match`

Structs were already structures and inout parameters already returned tuples;
now they are kernel-transparent, so the §11.2 frame laws hold by `simp`
(`(move_start s v).2.end = s.end`). Two enum bugs found by the fixtures were
fixed in the generator:

- named-field enum patterns (`Shape::Rect { h, w } => …`) produced a Lean
  `{ … }` structure pattern on an inductive and failed to compile; they are now
  positional constructor patterns in declaration order, with `_` for omitted
  fields;
- enum variant literals (`Shape::Rect { w: 6, h: 7 }`) referenced a
  nonexistent `«Shape::Rect»`; they are now the constructor applied in
  declaration order, after evaluating operands in source order.

### 4. `Fail` and state effects

- `Never`-returning operations (`Fail::raise(e)` in value position) returned
  `Empty` where the branch expected the surrounding type; the result is now
  `Empty.elim`'d.
- Model monads for `Fail[E]`: `instance : Effect_Fail E (Except E)` and
  `instance [Monad m] : Effect_Fail E (ExceptT E m)`, so a checked-arithmetic
  function can be run and reasoned about at `m := Except ArithOverflow`.
- State effects are lexical handlers (`HandlerCPS` folds); a closed function
  with a stateful handler now reduces in the kernel (`twice 5 = 11 := rfl`).

### 5. User contracts as Lean propositions

There is no contract syntax in the source language (and this lane may not add
attribute syntax), so the extractor uses the convention Crucible's
`verify --refute --contract/--requires` already uses: bool predicates over the
function's parameters. For a function `f` with `ensures_f(params…, result) ->
bool` and optionally `requires_f(params…) -> bool`, the module gains
`f$contract : Prop`:

| `f` | proposition |
| --- | --- |
| pure, non-recursive | `∀ x, requires_f x = true → ensures_f x (f x) = true` |
| `Fail[E]`, non-recursive | `∀ x, requires_f x = true → ∀ r, f (m := Except E) x = .ok r → ensures_f x r = true` |
| pure, recursive | `∀ x, … → ∀ fuel r, f$fuel (m := Option) fuel x = some r → ensures_f x r = true` |
| `Fail[E]`, recursive | same over `(f$fuel (m := ExceptT E Option) …).run = some (.ok r)` |

Anything else is a typed `lean::ContractError` (wrapped in
`ExtractError::Contract`): predicates that are effectful, generic, recursive,
take inout parameters or do not return `bool` (`Predicate`); predicates whose
parameter types do not match (`Signature`); and contracted functions that are
generic, take inout parameters, have open rows or effects other than one
unlabeled `Fail[E]`, or have no total form (`Unsupported`).

## Public API (additive)

- `vesper::lean::extract_report(&World) -> Result<Extraction, ExtractError>`,
  with `Extraction { module, totality: BTreeMap<String, Totality>, contracts }`.
- `enum Totality { Total, Fuel, Partial(String) }`, `enum ContractError`,
  `enum ExtractError { Contract(ContractError), Unsupported(String) }`.
- `extract` and `extract_module` keep their signatures (errors as `String`).
- `vesper_lean_syntax`: `Term::references()` and `DefinitionKind::SimpDef`
  (`@[simp] def`).

Generated-output changes: non-recursive functions are `def`, ordered, outside
`mutual`; `$block_*` helpers are `@[simp] def`; new prelude class
`VesperDiverge` and its instances; `Effect_Fail` model instances when the
world has `Fail`; `f$fuel` companions and `f$contract` propositions.

## Fixtures and what each proves (Lean 4.24.0, no `sorry`)

`tests/lean_extract.rs` extracts each fixture, checks the reported totality
and the reference evaluator's `main`, compiles extraction + proof script,
prints `#print axioms` for every theorem and fails on `sorryAx` or
`Lean.ofReduceBool`. Proof scripts may not use `sorry`, `admit`,
`native_decide`, `bv_decide` or `axiom`.

| Fixture | Forms | Theorems |
| --- | --- | --- |
| `structs` | structs, nested inout projections | `swap` exchanges fields; `move_start` writes `start.x` and preserves `start.y` and `end`; `main = 2` |
| `enums` | enums, named/positional/wildcard patterns, checked `*` | rectangle area is `.ok (w*h)` when the exact product fits and `.error ArithOverflow.mk` when it does not; `is_round s ↔ ∃ r, s = .Circle r`; `main = 42` |
| `recursion` | recursion over an ADT, over a counter, mutual recursion | `length$fuel` on a two-element list; ∀ fuel n r, `drain$fuel … = some r → r = 0` (induction on fuel); parity of 10 and 7; zero fuel is `none` |
| `loops` | tail-recursive bounded loop with checked `+` | `triangle 10 = 55` through `ExceptT ArithOverflow Option`; too little fuel diverges |
| `effects` | stateful handler, `Fail::raise` in value position, `Fail` handler | `twice 5 = 11`; `checked_halve` ok/error; handled `halve_or_zero 7 = 0`, `10 ↦ 5` |
| `contracts` | pure, `Fail`, recursive contracts | `clamp$contract`, `add_small$contract` (under its precondition), `countdown$contract` (induction on fuel), all for every input |

Negative tests: five malformed contracts give the expected `ContractError`
variant; recursion through a function value is `Totality::Partial("…as a
value")` and a contract on it is `ContractError::Unsupported`; a
non-recursive program contains no `partial def` and is ordered callees first.

These are theorems about the extracted Lean model of each fixture. They are
not theorems about the Rust compiler, native code, or the faithfulness of the
extraction to the checker's semantics (that is still argued, and checked by
evaluator agreement, not proved).

## Decisions

- **Fuel, not `termination_by`.** The source has no `decreases` annotations
  and recursion is split across CFG blocks, so Lean cannot find measures
  itself. Fuel gives every recursive function a total form with one uniform
  proof principle; divergence is an explicit effect, so no theorem can rely on
  a made-up exhausted value. Structural `termination_by` for ADT recursion is
  a possible later refinement.
- **Executable form unchanged for recursive groups.** Keeping the
  `partial def`s preserves the `#eval` agreement tests; companions are
  additional definitions.
- **Contract convention instead of syntax.** `requires_f`/`ensures_f`
  predicates match Crucible's contract shape, so the same predicates can be
  refuted by `vesper verify --refute` and proved in Lean.
- **`tests/lean_effect_ast.rs`.** Its structural test asserted that functions
  sit in a `mutual` block, which is exactly what this lane changes for
  non-recursive code. The assertion now accepts a recursive `mutual` block or
  `main` as an ordinary definition. It is one hunk in its own commit.

## Lens (read only) and which recorded gaps this closes

Lens' report lists these gaps for its semantic lenses: "no structs, linear
values, effects other than `Fail`, loops via recursion, `match`, or user
contracts", and "the kernel sees only opaque constants for `partial def`s".
With this lane:

- non-recursive functions over structs, enums, `match`, `Fail` and handled
  state effects are ordinary definitions the kernel can unfold, so a Lens
  obligation can be stated over the extraction itself rather than Lens' own
  scalar model;
- recursion and loops have `f$fuel` companions with a partial-correctness
  proof principle;
- `f$contract` gives Lens a ready proposition per contracted function, and
  `extract_report(..).totality` tells it which functions are kernel-visible.

Lens itself was not changed (not this lane's path). Wiring a lens to
`f$contract` and to `Totality` is the remaining step on Lens' side.

## Remaining gaps

- Companions are not generated for recursive functions used as first-class
  values; those stay `Partial` with the reason.
- Contracts over inout parameters, generic functions, labeled or multiple
  `Fail` rows and non-`Fail` effects are rejected with typed errors.
- Proofs over `UInt64` need `UInt64.toNat` rewriting (`simp […toNat…]; omega`);
  no Vesper-specific simp set is generated yet.
- The equivalence between a `partial def` and its companion (for enough fuel)
  is not proved; the kernel cannot see the `partial def`.
- No `decreases` source syntax, so no `termination_by` output.
