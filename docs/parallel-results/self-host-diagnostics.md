# Self-hosting SH1 lane 1: the vesper-diagnostics port

Claim: #1128 (SH0 lane 6, part 2). Plan:
`docs/agent-prompts/self-host-sh1/01-diagnostics.md`. Base: `e29e63d`.

This lane ports `vesper-diagnostics`, the crate every compiler error goes
through, to Vesper. The port does the checks of `prepare`, writes the LSP
JSON, and renders ariadne 0.5.1's terminal report byte for byte, with colors
off and on. Rust stays the default: the compiler links the frozen Rust seed
copy, and nothing Rust is deleted.

## What changed

The crate uses the seed pattern of `vesper-span` (#1138):

- `crates/vesper-diagnostics/seed/` is the package `vesper-diagnostics-seed`
  with the library name `vesper_diagnostics`, built from the same
  `src/lib.rs` without a build script, so it is plain Rust. The root package
  and `vesper-hybrid` (which mirrors the root's dependencies) depend on it by
  rename; that switch is its own commit.
- The original package always builds the Vesper port through
  `vesper_port_harness::Port::build` (cfg `vesper_port`). Its public API is
  unchanged. Two methods are new in both builds: `Prepared::lsp_json`, the
  compact JSON array an LSP server sends, and `Prepared::terminal_colored`,
  the report with ariadne's default colors (the crate only ever rendered
  with colors off, so this is how colors-on is reached and tested).
- `tests/differential.rs` checks the port against the seed (the dev-dependency
  is renamed `diagnostics-seed`, as span's is, to avoid E0464).
- `tests/port_memory.rs` checks that the port frees everything it allocates,
  on success and on the error paths.
- `port/test-port.sh` builds three divergent ports (feature
  `vesper-port-divergent`, chosen by `VESPER_DIAGNOSTICS_DIVERGE`) and requires
  a named test to fail on each. It is appended to Linux port shard 7.

### The Vesper package (crates/vesper-diagnostics/vesper: 1,865 lines, plus 60 generated)

- `prepare_check`: `Limits::validate`, the source, line, diagnostic, label,
  text, metadata and work budgets, and the span checks (reversed,
  out of bounds, UTF-8 boundary, CRLF interior), in the Rust order, so every
  error is the same. Rust encodes only lengths and spans (7 words per
  diagnostic, 3 per related label), never the text, and stops at the
  diagnostic whose label count passes the budget. The copies and
  `vesper_span::Diagnostics::new` stay in Rust (they are `vesper-span`'s).
- `lsp`: the name check, the work, output and metadata preflights, and the
  JSON. It computes UTF-16 positions from its own line table and escapes
  strings as serde_json does (`\b \t \n \f \r`, other controls as
  `\u00xx`). `to_lsp` parses the result with serde_json, because its API
  returns `Vec<Value>`.
- `terminal`: the preflights, the unsupported-separator refusal, and
  ariadne's `write_for_stream` as the crate configures it: one source, labels
  in order, every label with a message, `Config::default()` with byte
  indices. Each function names the ariadne part it follows: source groups,
  line ranges, margins (`write_margin` with its corner, cross and arrow
  rules), multi-line labels sorted by length, the label rows, `trim_end`,
  tabs, the help lines (`str::lines`), and the yansi escapes for colors
  (`ESC[31m`, `ESC[38;5;Nm`, `ESC[0m`, one per painted piece, as yansi
  writes them).
- `width.ves` is generated by `examples/width_table.rs` from unicode-width
  0.1.14 (`UnicodeWidthChar::width`, with ariadne's `unwrap_or(1)` for
  control characters: 497 runs) and Rust's `char::is_whitespace` (10 runs).
  `tests/port_tables.rs` fails if the committed file differs from the
  generator's output.

Divergent builds:

| Area | Change | Test that catches it |
| --- | --- | --- |
| prepare | the source's line count is not charged | `existing_index_must_fit_renderer_line_profile` |
| lsp | a 4-byte char counts one UTF-16 unit | `actual_utf8_bytes_become_utf16_ranges_and_all_actual_labels` |
| terminal | tabs stop every 3 columns | `generated_reports_render_identically` |

The `prepare` divergence is the line budget, not a span check: the span
checks are also made by `vesper_span::Diagnostics::new` afterwards, so a
dropped span check still fails, just later.

### Byte-identical output

`tests/differential.rs` compares the builds on:

- 600 generated inputs that pass `prepare` (717 tried), each rendered under
  two names: 973 terminal reports, 1.19 MB, identical with colors off and
  on. Sources mix ASCII, tabs, CJK and fullwidth text, emoji, combining
  marks, zero-width and Unicode spaces, controls, CR, LF and CRLF, long
  lines and trailing terminators. Labels are zero-width, short, long,
  multi-line, overlapping or invalid. Messages and helps have newlines,
  CRLF, trailing newlines, quotes, escapes and controls. Some inputs get
  small budgets, so errors are compared too.
- 80 dense reports with up to 25 labels on a few lines, where the margin and
  arrow rules interact most.
- the inputs of the crate's own tests.

Every `prepare` result, every terminal report and every LSP array (both
parsed with serde_json) matches, errors included. The crate's 14 tests pass
on both builds.

### Outside the exclusive paths

- `crates/vesper-hybrid/Cargo.toml`: its copy of the root dependencies takes
  the seed too (`tests/manifest.rs` keeps the two lists in step).
- `scripts/test-port-harness.sh`: one line for shard 7.
- `tests/fixtures/self_host/driver.rs`: the self-host driver skips the new
  `vesper/` directory, which uses `use` and `t[a..b]` intervals that the
  Stage 1 compiler package does not parse yet (#880, #887).

## Numbers

Linux x86_64 cloud container, release builds. The workload is one report of
200 labels: 25 diagnostics of 8 labels over a 9 KiB source with tabs, wide
chars and CRLF, some labels multi-line, each with a two-line help. One
diagnostic with 200 labels is refused by the crate's own work budget in both
builds (the terminal preflight charges the fourth power of a diagnostic's
label count), so the 200 labels are spread over 25 diagnostics. ABBA is 30
epochs with the median per operation (`examples/abba.rs`, run by
`scripts/bench.sh`). Instructions are from callgrind, as the difference
between runs of 6 and 1 batches (`CALLGRIND=1 scripts/bench.sh`).

| Workload | Rust per op | Vesper per op | ABBA Vesper/Rust (min-max) | Rust Ir | Vesper Ir | Ir ratio |
| --- | --: | --: | --- | --: | --: | --: |
| `prepare` | 33.1 µs | 39.1 µs | 1.19 (1.07-1.27) | 2.00M | 2.38M | 1.19 |
| `terminal` (colors off) | 1.65 ms | 1.12 ms | 0.68 (0.65-0.71) | 77.7M | 43.8M | 0.56 |
| `terminal_colored` | 1.89 ms | 1.33 ms | 0.70 (0.63-0.78) | 95.9M | 50.5M | 0.53 |
| `lsp_json` | 309 µs | 121 µs | 0.39 (0.31-0.42) | 18.4M | 6.0M | 0.33 |
| `to_lsp` (`Vec<Value>`) | 282 µs | 408 µs | 1.47 (1.31-2.56) | 13.3M | 21.2M | 1.60 |

The renderer is faster because ariadne formats every char and box piece
through `write!` and recomputes iterator chains per column, while the port
appends bytes into one buffer. The JSON is faster because Rust builds a
serde_json DOM and then serializes it; the port writes the bytes directly.

Not at parity:

- `prepare` (1.19x). The checks are cheap; the cost is the two encodings the
  port adds around the unchanged Rust copies and `Diagnostics::new`: the
  check input (lengths and spans) and the checked model with its text pool,
  which every render reads. A tree or record export ABI (gap 4, SH1 lane 6)
  would remove both.
- `to_lsp` (1.47x). Its API returns a serde_json DOM, so the port parses its
  own JSON. An LSP server should call `lsp_json`, which is 0.39x. Nothing in
  the compiler can close this while the API returns `Value`s.

So Rust stays the default (the user's parity rule), and the seed stays what
the compiler uses.

## Compiler gaps

1. **A guard against a constant does not bound a constant-array index.**

   ```vesper
   const N: u64 = 3;
   const T: [u64; 3] = [1, 2, 3];
   pub fn f(i: u64) -> u64 { if i < N { T[i] } else { 0 } }   // E0401: Fail
   ```

   Only a literal bound works (`if i < 3`). Workaround: the table generator
   writes the run counts as literals into the lookups (`width.ves`).

2. **`&&` does not carry its left fact to its right operand.**

   ```vesper
   const T: [u64; 3] = [1, 2, 3];
   pub fn f(i: u64, c: u64) -> u64 { if i < 3 && c <= T[i] { 1 } else { 0 } }   // E0401
   ```

   Workaround: nested `if`s (`char_width`).

3. **No `\u{..}` or `\x..` string escapes.** `"\u{1b}[0m"` and `"\x1b"` are
   E0002, so an ANSI escape cannot be a literal. Workaround: `out.push(27)`
   before the literal rest (`open`, `close`).

4. **Records still need hand-written flat encodings.** `src/port.rs` encodes
   the diagnostics twice (the check input and the checked model with a text
   pool), which is most of `prepare`'s 1.19x. A record or tree export ABI
   (SH1 lane 6) would let the port read `DiagnosticData` directly.

5. **Another crate's types cannot cross the export ABI.** The binding
   implements `vesper_port_abi::Abi` for the Rust types the Vesper types
   name, and the orphan rule forbids that for `vesper_span::Error`,
   `vesper_span::Resource` or `vesper_span::Limits`. The port mirrors them
   (`Failure`, `Res`, `Caps` in `src/port.rs`) and converts. A binding mode
   that converts through a local mirror, or that lets a dependency's own
   binding provide the impls, would remove the mirrors.

6. **`use` cannot name a constant** (known since #1091): the lookups have to
   live in `width.ves` beside the generated tables instead of in `lib.ves`.

## What is left

- `prepare` and `to_lsp` parity (gaps 4 and 5, and the `Vec<Value>` API).
- Notes (`with_note`) and other ariadne configurations are not ported,
  because the crate never uses them; the port covers exactly what
  `terminal` asks ariadne for.
