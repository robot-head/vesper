# Current-source macro preview acceptance

Claim: [#154](https://github.com/robot-head/vesper/issues/154), branch
`preview41/acceptance`. This lane owns only its new fixtures, actual executable
acceptance, wrapper, workflow and this report. Production integration belongs to
#152, #153 and #155 under `docs/rfcs/preview41-contracts.md`.

The five independent Rust stdio tests verify exact current-source and expanded
BLAKE3 hashes, opt-in capability and response scope, unchanged repeated requests,
ordinary parse-error publication/hover unavailability, same-header helper body
authority drift, actual linear rejection, no accepted maps/audits on rejection,
more than64 accepted revisions, no-op updates, stale expected versions, stale
changes, close/reopen, foreign URIs, strict client parameter rejection and source
resource refusal. Oversized store changes preserve the previous document;
oversized opens leave the URI unopened. A separate source below the store byte
cap exceeds the real compiler's function inventory limit and returns a structured
resource rejection. Response reads and execution waits have finite limits.

The Python executable harness additionally verifies both hygiene directions,
distinct expanded provenance spans for repeated input, actual E0303 related
spans, strict duplicate-key/framing decoding and UTF-8 byte anchors. It compares
successful preview artifacts/maps/audits with a separate actual `forge check`
invocation. A real on-disk program deliberately differs from the current open
unsaved program; responses must use the latter and leave the file untouched.
The harness invokes normal `check` and `run` separately on positive expanded
artifacts to obtain42. Preview itself never invokes execution. Unsupported WASI
source annotation refuses rather than loading a referenced component.

The native Linux, macOS and Windows workflow runs actual query/provider/stdio
tests, existing editor/recovery/compiler authority guards, strict Clippy and the
Python harness. Its normal dependency check excludes the Wasmtime engine. No
fake executable, manufactured checked artifact, ignored test or timing claim is
used. The wrapper accepts `VESPER_MACRO_PREVIEW_BINARY` for a read-only actual
integration executable; ordinary Cargo tests use the actual Cargo binary.

Validation so far: standalone Rust test compilation and strict Clippy against
the existing serde_json/blake3 artifacts passed; rustfmt, Python compilation,
Bash syntax, framing UTF-8 roundtrip, duplicate-key guard and whitespace checks
passed. Actual runtime acceptance is pending the real #155 integrated executable.
These static checks are not reported as executable macro-preview acceptance.
