# Integration B: CLI and compiler hooks for the wave-five crates

Claim: #136 (wave five, run in wave six). Branch `claude/project-thread-qf5iax`,
based on `main` at `11e0d9d` (contains Silicon #149, Chorus #151 and eBPF #163).

Integration B wires the wave-five host libraries into the root `vesper`
package: five commands, one verifier hook on the native backend, one shared
stack-bound report, and a TEE measurement for `vesper build`. No crate under
`crates/**` was edited; only APIs already on `main` are used.

## The hook point (for lanes 23 and 24)

`src/native.rs` gained one observer parameter on its private `compile`, and
one public entry point:

```rust
pub struct EmittedFunction {
    pub key: String,            // monomorphized instance key
    pub source: String,         // source function name
    pub symbol: String,         // object/JIT symbol
    pub func_id: u32,           // cranelift_module FuncId; function.name == u0:<func_id>
    pub function: ir::Function, // finalized IR, cloned before machine-code generation
    pub callees: Vec<(u32, String)>, // every referenced function, defined or imported
}

pub fn object_with_observer(
    world: &World, entry: &str, target: Option<&str>, optimize: bool,
    observer: Option<&mut dyn FnMut(EmittedFunction)>,
) -> Result<(Vec<u8>, String), String>;
```

`object_with_options` is now `object_with_observer(.., None)`. The observer
receives a clone after `FunctionBuilder::finalize` and before
`Module::define_function`, so it cannot change code. The JIT, the native batch
and the session backends call the unchanged `define_instances` (observer
`None`). `tests/native_verifiers_cli.rs::programs_compile_to_identical_code_without_verifier_flags`
compiles every example and fixture with an entry `main` for x86_64 and
AArch64 and checks that the object bytes and CLIF are identical with no
observer, with an observer, through the CLI without flags and through the CLI
with `--verify-const-time`.

Lane 23 (native coverage) should add its instrumentation as its own explicit
flag next to this hook, not inside the observer (the observer only sees IR).

`src/native_verifiers.rs` (public module `vesper::native_verifiers`):

- `NativeVerifier::{ConstTime, Stack, Realtime, DetFloat}`, `parse_verifier_list`,
  `NativeVerifier::from_flag`.
- `NativeVerifierPolicy` (JSON, schema `vesper.native-verifiers/1`, unknown
  fields rejected) with sections `const_time` (per function: `secret`
  parameter names, `declassify`, `constant_time_callees`), `stack` (`arch`,
  `roots` name → budget bytes, `external_bounds`), `realtime` (`roots` name →
  optional stack budget, `allowed_effects`, `symbols` import → effects and
  frame bytes, `effects` per source function, `loop_bounds`,
  `reject_unbounded_loops`, `max_loop_iterations`), `det_float`
  (`functions`, `allow_fma`, `allowed_float_calls`, `reduction_order`).
- `emit_and_collect(world, entry, target, optimize)`,
  `verify_emitted(world, &[EmittedFunction], target, &verifiers, &policy) -> NativeVerifierReport`,
  `verify_native(..)` (both), `render(report, file, source)`.
- `NativeFinding { verifier, function, inst, rule, message, span }`: the
  function is the source instance key (verifier names `u0:N` are mapped back),
  the span is the source function's byte span; `render` prints
  `file:line:col` of the item. Instruction-level source spans are not
  available because the backend attaches no source locations to Cranelift
  instructions.

Lane 24 should build a `NativeVerifierPolicy` from lane 15's capability
policies and call `verify_emitted`; the hook point does not need to change.

Parameter mapping for `const_time`: a by-value scalar parameter at source
position `i` is entry-block parameter `i` (plus one when the result is
returned through an sret pointer) and becomes a Vault `secret_params` entry;
an `inout` scalar or an aggregate parameter is a pointer and becomes a
`secret_pointer_params` entry. Generic functions are rejected in `const_time`.

Per verifier:

- **const-time**: `vesper_vault::verify_constant_time` on each function the
  policy names. Callee names are translated to Cranelift display names.
- **stack**: `vesper_silicon::stack::Program::compile` re-compiles the emitted
  IR for x86_64 or AArch64 (policy `arch`, else the `--target` architecture,
  else the host), measures prologues and builds the call graph; the graph
  goes through the shared report below. Imports such as `fmod` are external
  calls that need an `external_bounds` entry.
- **realtime**: `vesper_resonance::clif::call_graph_from_clif` with names for
  every `u0:N` and the policy's symbol table, then `verify_realtime`. An
  import absent from `symbols` is an unknown callee, rejected when reachable.
- **detfloat**: `vesper_kinetic::audit` on every emitted function (or the
  listed ones). Calls between audited emitted functions are allowed, because
  each callee is audited itself. The backend does not enable Cranelift NaN
  canonicalisation, so float arithmetic whose result escapes is reported as
  `detfloat.nan-escape` and imported libm calls as `detfloat.libm`; that is the
  auditor's rule set, not a bug in the hook.

With no policy file the policy is empty: const-time and realtime then check
nothing and say so in a `note:` line, stack reports recursion and unbounded
calls only, and detfloat audits everything. Any finding fails the command
(exit 1, `N native verifier finding(s)`); findings go to stderr so
`emit --emit clif` output stays clean.

## The shared stack-bound report

`vesper::stack_bound` converts either crate's `CallGraph` (they are distinct
types with the contract's shape) into `StackGraph` and analyses it with one
algorithm, Silicon's `analyze_stack` (recursion, unresolved indirect calls,
unbounded external calls, per-root worst path and budget). For graphs from the
eBPF verifier the kernel's rules are also checked with
`vesper_ebpf::callgraph::check_stack` (512 bytes combined, at most 8 frames):
a violation is `ebpf.stack.kernel_limit`, and a disagreement between the two
worst-case numbers is `stack.analyzers_disagree` instead of being resolved
silently. Malformed graphs (sparse ids, unknown ids) are errors. `vesper ebpf
check` and `--verify-stack` both print this report.

## Commands

**fuzz.** Targets take `i64`, `u64`, `u32`, `u8` or `bool` parameters passed
by value; anything else is a typed error. One `Runtime` is reused across
executions (lowering and optimising once, fuel reset per call). A run fails
when the evaluator returns an error (an escaping `Fail`, an abort); fuel
exhaustion is an invalid run, not a failure. Failure kinds drop digits so a
shrunk input must fail the same way. `--native` also compiles a zero-argument
wrapper per input with the native batch backend and fails on any
evaluator/JIT disagreement; it is limited to effect-free targets inside the
batch subset (checked up front, typed error otherwise).
`--differential <fn>` compares every outcome with a shadow function of the
same signature and reports `divergence`; it prints the `vesper-migrate`
shadow limitation and that isolation was unavailable (both sides run in the
evaluator). `--corpus <dir>` replays saved `*.tape` files first (a failing one
is shrunk and reported) and saves the campaign corpus afterwards.
`--regressions <file>` writes the input module plus a `// @test regression`
comment and a zero-argument function calling the target with the shrunk
arguments and the target's effect row, formatted canonically and re-checked;
repeated runs add `_2`, `_3`, ... The source language has no `@test`
attribute yet, so the marker is a comment.

Coverage guidance is coarse: the outcome class and value are reported as
probe edges, and every integer literal in the module is reported as an
equality comparison against each drawn argument (in tape encoding) so
Crucible's input-to-state solver can substitute it. This found the magic
`(200, 200)` divergence and `not_magic(4660, true)` in the tests. Native edge
and comparison instrumentation is lane 23.

**verify --refute.** The contract is a `bool` source function over drawable
parameters; `--requires <fn>` is a precondition (a false precondition is an
`assume` rejection). Uses `vesper_crucible::refute`, which only reports
`Refuted` after regenerating the input from the shrunk tape and re-checking.
An evaluation error in the contract is `Crashed`, reported as "could not be
evaluated", never as a refutation. Survival prints "no counterexample found
within budget"; exit 0. Extracting predicates from Lean models and seeding
`bv_decide`/`aesop` with the witnesses are not done.

**migrate.** `.h` files go to `c::analyze_header`, `.rs` files to
`rust::analyze_source`, directories to `rust::analyze_crate_dir`. Writes
`<stem>.ves` (`synth::vesper_declarations`) and `<stem>.migrate.txt`
(`synth::report`); writes `<stem>.vsys` (`synth::sys_spec`, already parsed by
the Bridge) only with `--artifact <file>`, whose BLAKE3 the spec pins, because
a spec must not pin an invented digest. The `.ves` output is the migrate
declaration syntax (`extern fn`, `@wire_layout`), which the current Vesper
parser does not accept; it is a review artefact, as in the crate's goldens.

**replay.** Opens the bundle with its key (MAC before parsing, then structural
validation), prints a summary, replays every record from the initial state
through a transcript replayer (a BLAKE3 chain) when nothing was evicted,
lists the timeline (`--timeline`), runs a reverse watch on an `inout` place
(`--watch <hash> [--before <seq>]`), prints an obligation's provenance
(`--lineage <id>`) and the lineage audit, and exits 1 when an obligation
leaked. Reconstructing program state needs a domain `Replayer`; the CLI has
none, so `state_at` from snapshots is not exposed.

**ebpf check.** Reads BPF ELF objects (`vesper_ebpf::elf::read_object`), raw
slot bytes, or text with one 16-hex-digit slot per line. Rejections print
`error[<rule>]: <prog> at insn <n>: <message>`. Accepted programs get the
shared stack report (`--stack-budget`, default 512). `--load` loads through
`vesper_ebpf::kernel` on Linux and prints `kernel: unavailable` where `bpf()`
is refused or off Linux. A textual assembler is not provided.

**build --tee.** After linking, digests the executable with BLAKE3 and writes
`<exe>.tee.json` with the TDX RTMR value of one SHA-384 extend padded to 48
bytes (`vesper_aegis::claims::single_extend`, exactly what
`vesper_aegis::tdx` checks for RTMR[2]/RTMR[3]) and the CCA REM form
(SHA-512, 64). No hardware extend happens: there is no TDX or CCA guest at
build time, and the file says so.
