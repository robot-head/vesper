Functions and bindings

A function declares its parameter types in parentheses and its result type after ->. The last expression in its body supplies the result. Here both branches of if produce an integer. The caller can use the entire expression as a value.

fn larger(left: i64, right: i64) -> i64 {
    if left > right { left } else { right }
}

fn main() -> i64 {
    let high = larger(12, 9);
    larger(high, 15)
}

i64 is a signed 64-bit integer. The compiler infers the type of high from the call. The semicolon ends the binding, and the final call returns 15 from main.

What the shell sees

vesper run prints the value of main. For a native executable, main can return an integer or Unit. On Linux, the shell sees the low eight bits of an integer result after a normal exit. Choose 0 for success and a small positive status for failure when writing a command-line tool.

The Fibonacci example returns 55 for fib(10). Its overflow handler returns -1. If that handler runs, the evaluator prints -1 and the native executable gives the Linux shell status 255. Try both commands. Linux exit status reference.

Run the example

  1. Clone the repository and build the compiler. Build Vesper from source.
  2. Save the example as lesson.ves in the repository root.
  3. From that directory, run both commands below. check checks the source. run evaluates main and prints 15.
cargo run --locked -p vesper -- check lesson.ves
cargo run --locked -p vesper -- run lesson.ves

Loops and ranges

Use let mut for a local you intend to update. This loop adds the integers from one through four. The u64 annotation makes the accumulator an unsigned 64-bit integer.

fn main() -> u64 {
    let mut total: u64 = 0;
    for n in 1..=4 {
        total = wrapping_add(total, n);
    }
    total
}

The inclusive range 1..=4 gives a total of 10. Change the range to 1..4 and the loop stops before four, giving 6. Removing mut makes the assignment to total a checker error.

Use continue to skip the rest of an iteration and break to leave the innermost loop. When you need the loop itself to yield a value, use loop { … } and supply the value with break value. See nested loops and early returns.

Enums and pattern matching

An enum describes a value that takes one of several forms, called variants. Each variant can carry its own data. Use match to choose an arm and bind the payload in the same step.

copy enum Reading {
    Missing,
    Sample(i64)
}

fn value_or(in reading: Reading, fallback: i64) -> i64 {
    match reading {
        Reading::Missing => fallback,
        Reading::Sample(n) => n,
    }
}

fn main() -> i64 { value_or(Reading::Sample(17), 0) }

Reading::Sample(17) selects the second arm and binds n to 17. Pass Reading::Missing to select the fallback. The checker requires the arms to cover every possible input. A final _ matches any remaining value. Naming each variant lets the checker point out matches that need attention when you add another variant.

The built-in Option[T] uses this same pattern for values that may be absent. Match Some(x) to use the payload and None to handle its absence. See patterns with nested records and optional values.

Ownership modes

A transaction must finish even if its caller takes an early return. Declaring it linear makes the owner account for it on every path. Use the ownership mode that matches the lifetime of your value.

copy
You can duplicate or discard the value. Use it for data such as the integer reading above.
affine
You can transfer ownership or let the value drop. After a move, only the new owner can use it.
linear
You must account for the value at scope exit. Consume it locally, pass ownership to a callee, or return it to your caller.
linear struct WriteTxn { wal_slot: u64 }

impl WriteTxn {
    fn commit(sink self) -> u64 {
        let WriteTxn { wal_slot } = self;
        wal_slot
    }
}

fn main() -> u64 {
    let tx = WriteTxn { wal_slot: 42 };
    tx.commit()
}

sink self transfers the transaction to commit. Destructuring self consumes the record and binds its slot number. The caller receives 42. A second call on tx would use a moved value. Replacing the first call with a literal 42 would leave the transaction live at scope exit.

The full example also defines abort(sink self). An application can choose either outcome while satisfying the same ownership rule. Read the complete transaction example.

Parameter modes and field loans

A parameter mode describes the access a callee receives. Use in for a shared read, inout for exclusive access to update a place, and sink to take ownership. A place is a storage location such as a variable or one of its fields.

copy struct Broker { index: u64, metrics: u64, config: u64 }

fn append(inout broker.{index, metrics}: Broker, in config: u64) {
    broker.index = wrapping_add(broker.index, config);
    broker.metrics = wrapping_add(broker.metrics, 1);
}

fn main() -> u64 {
    let mut broker = Broker { index: 1, metrics: 0, config: 41 };
    append(inout broker, in broker.config);
    broker.index
}

Read the call together with the signature. The projection .{index, metrics} restricts the exclusive loan to those two fields. The separate argument reads broker.config, a disjoint field. After the call, index is 42 and metrics is 1.

Inside append, change the first assignment’s destination to broker.config. The checker reports E0304 because config falls outside the declared projection. Restore the assignment to broker.index to make this call valid again. To give a helper permission to update a field, name that field in its inout projection. Read the field projection example.

Checked arithmetic and effects

A function’s effect row, written eff […], lists effects that its caller must handle or pass on. Dividing a constant by a caller-supplied integer can raise Fail[RuntimeError] when the divisor is zero. Put a handler around the call to choose a recovery value.

fn divide(divisor: i64) -> i64 eff [Fail[RuntimeError]] {
    84 / divisor
}

fn main() -> i64 {
    handle Fail[RuntimeError] in {
        divide(0)
    } with {
        return value => value,
        raise(error, _) => match error {
            RuntimeError::DivisionByZero => 42,
            RuntimeError::IndexOutOfBounds => 0,
        },
    }
}

divide(0) reaches the raise clause and returns 42 through the division-by-zero arm. Try divide(4) to take the ordinary return clause and get 21. Since the handler covers the failure, main can omit that effect from its own signature. Read the checked division example.

Overflow uses a different effect, Fail[ArithOverflow]. For example, adding two arbitrary i64 values with + can overflow. Use checked addition when the caller should decide how to recover. Use wrapping_add when modular arithmetic is part of the algorithm, as it is for the broker’s counters. See checked addition in a recursive function.

Propagating a Result

Return Result[T, E] when you want your caller to receive either a value of type T or an error of type E. A caller can match both variants, or apply ? to continue with the value from Ok. On Err, the operator performs Fail[E] with the error payload.

fn port(n: i64) -> Result[i64, i64] {
    if n < 1 { Err(n) } else { Ok(n) }
}

fn main() -> i64 {
    handle Fail[i64] in {
        port(0)?
    } with {
        return value => value,
        raise(error, _) => 8080,
    }
}

port(0) returns Err(0). Applying ? routes that payload to the handler, which supplies the default port 8080. With port(443)?, the handled block yields 443.

Account for live linear resources before propagating a failure. If a transaction is live at validate()?, the error path could skip a later commit. The checker reports that the failure would discard the transaction. Validate before opening the transaction, or match the result and consume the transaction on each path. Read the rejected transaction.

Resuming an operation

A handler can supply an answer to an operation and let the computation continue from the call. Declare a linear effect for a handler that must resume exactly once. Here Ask requests an integer, and the handler chooses the answer locally.

linear effect Ask {
    fn ask() -> i64;
}

fn main() -> i64 {
    handle Ask in {
        wrapping_add(Ask::ask(), 1)
    } with {
        return value => value,
        ask(resume) => {
            let answer = resume(20);
            wrapping_mul(answer, 2)
        },
    }
}

At Ask::ask(), control passes to the ask clause. Calling resume(20) supplies 20 at that point. The addition produces 21, which passes through the return clause and becomes the result of resume. The handler then doubles 21, so main returns 42. See the same handler with checked arithmetic.

Closures and captures

A closure combines a function with values from the scope where you create it. In offset, value is a parameter and amount is a capture. Returning the closure lets the caller reuse that particular offset.

fn offset(sink amount: i64) -> fn @copy (i64) -> i64 {
    |value| wrapping_add(value, amount)
}

fn main() -> i64 {
    let add_ten = offset(10);
    add_ten(add_ten(2))
}

The return type describes a copyable function that takes an i64 and returns an i64. Its only capture is a copyable integer. Both calls add the captured 10. The inner call returns 12 and the outer call returns 22.

If the body uses checked +, the returned function type also needs eff [Fail[ArithOverflow]]. The addition runs when the caller invokes the closure. Wrap that invocation in a handler, or include the effect in the caller’s row. Read the example that composes two checked closures.

Generics and trait bounds

Introduce a type parameter in square brackets to write one function that works with several types. State the operations its body needs. This version of larger needs to compare two borrowed values and copy the selected value into the result.

fn larger[T: mod copy](in a: T, in b: T) -> T where T: Ord {
    match a.cmp(b) {
        Less => b,
        _ => a
    }
}

fn main() -> i64 { larger(12, 9) }

T: mod copy constrains ownership. The where T: Ord bound makes the ordering method cmp available. When a sorts before b, the first arm returns b. Otherwise the function returns a, including on a tie. The integer call yields 12.

The caller can also supply a copyable record with an Ord implementation. The same comparison then uses the record’s ordering. See one generic function called with integers, booleans, and points.

Traits and named models

A trait groups operations under a common signature. An impl supplies the canonical implementation for a type. If a point has more than one meaningful score, give the alternative implementation a name with model.

struct Point { x: i64, y: i64 }

trait Score {
    type Out: mod copy;
    fn score(in self) -> Self::Out;
}

impl Score for Point {
    type Out = i64;
    fn score(in self) -> i64 { wrapping_add(self.x, self.y) }
}

model ByX: Score for Point {
    type Out = i64;
    fn score(in self) -> i64 { self.x }
}

fn main() -> i64 {
    let p = Point { x: 3, y: 4 };
    let sum = p.score();
    let x = { use model ByX; p.score() };
    wrapping_add(sum, x)
}

Out is an associated type. Each implementation chooses the concrete type returned by score. Here both choose i64. The first p.score() uses the canonical implementation and returns 7. Inside the block, use model ByX selects the implementation that returns 3. Adding the two scores yields 10.

For a single explicit call, write ByX::score(p). A block-local selection is convenient when several calls in the block should share a model. Read the example with nested model selections.

Table-driven test sugar

Test cases are syntactic sugar. Each // @case row gives one invocation of the same test function its own name and arguments. Place a test block beside the function it exercises. The test can call private functions in the same module. Use one // @case comment per set of arguments so the report identifies which input failed.

fn larger(left: i64, right: i64) -> i64 {
    if left > right { left } else { right }
}

test {
    // @case descending(12, 9, 12)
    // @case ascending(9, 12, 12)
    // @case tie(7, 7, 7)
    fn test_larger(a: i64, b: i64, expected: i64) -> bool {
        larger(a, b) == expected
    }
}

Save this example as lesson.ves and run the first command below to execute all three rows. The second command selects the tie case. Change the expected value in that row to 8 to see a failure reported for test_larger::tie.

cargo run --locked -p vesper -- test lesson.ves
cargo run --locked -p vesper -- test lesson.ves --filter test_larger::tie

To try the same techniques in larger programs, use the repository examples. The specification gives the formal rules for each feature. Example programs · Language specification (PDF)

Define your own sugar

A source macro gives an expression a new spelling. Here $x: expr accepts one expression, and quote supplies the code that replaces the call.

macro addone($x: expr) -> expr {
    quote { wrapping_add($x, 1) }
}
fn main() -> i64 { addone!(41) }

Save this as lesson.ves. Format the macro itself, then expand it to ordinary Vesper before running it. These commands use the compiler built in the repository and a POSIX shell.

target/debug/vesper fmt lesson.ves
target/debug/vesper fmt --check lesson.ves
target/debug/vesper forge expand lesson.ves > expanded.ves
target/debug/vesper run expanded.ves

The second formatting pass accepts the first pass’s output. The expansion calls wrapping_add(41, 1) and prints 42 when run. The manuscript also proposes a sugar declaration for forms such as a guard with an else clause. Read the design for extensible syntax.
