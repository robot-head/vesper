# Repository automation

The only permitted scripting for repository automation is native Aspect tasks written in Starlark (AXL) and Windows PowerShell entry points (`.ps1`) where Aspect cannot run. Never add Python, Bash, other shell scripts, or Windows batch files. This includes extensionless scripts and executable fixtures generated by tests.

This rule applies to GitHub Actions workflows, composite actions, BuildBuddy, and other configuration files. Keep scripting logic out of inline `run` and `script` blocks, heredocs, and interpreter command strings such as `python -c`, `bash -c`, and `pwsh -Command`. A step may invoke a native tool, Aspect task, or Windows PowerShell `.ps1` entry point directly. Put command sequences, conditionals, pipelines, and substitutions in the Aspect task or PowerShell file.

The Repository automation policy check enforces new violations in CI. Run it locally with `aspect ci check-automation-policy -- --base origin/main`.

When migrating an existing script, update its callers and tests to use the replacement and remove the original script.

# CI runners

Never start the Platforms workflow by hand, for a pull request or a branch. `Native platform checks` starts its macOS and Windows checks on its own once `Native and acceptance scripts` is green and no BuildBuddy check has failed. A hand start takes one of the account's 5 macOS runners and nine Linux port shards, and runs queued behind hand starts have waited hours. Leave reruns and hand dispatches to a maintainer.
